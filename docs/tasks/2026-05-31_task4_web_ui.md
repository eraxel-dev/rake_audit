# Task 4 — Web UI (Routes, Controllers, Views & Multi-Adapter Support)

## Goal

Deliver the browser interface mounted at `/rake_audit`: a dashboard with aggregate stats, a paginated and filterable execution list, and a detail page. Includes pluggable authentication and backend-agnostic data access so the Web UI works with any configured storage adapter (ActiveRecord, Redis, MongoDB, or custom).

## Dependencies

- Task 3 (Rails Engine, DB Layer & Generator) — provides the Engine mount point and `RakeAudit::TaskExecution` AR model used by `ActiveRecordAdapter`
- Task 2 (Storage Adapters) — `RedisAdapter` and `MongoAdapter` are extended with query methods here

## Adapter Query Interface

All adapters that back the Web UI must implement the following methods (stubs with `NotImplementedError` are defined in `Adapters::Base`):

| Method | Returns | Purpose |
|---|---|---|
| `query(filters:, page:, per_page: 25)` | kaminari-paginated collection | Filtered, ordered execution list |
| `find(id)` | execution record object | Single execution detail |
| `count` | Integer | Total execution count |
| `count_by_status(status)` | Integer | Per-status count |
| `average_duration_ms` | Float \| nil | Mean duration |
| `top_failed_tasks(limit: 10)` | `[[name, count], …]` | Top-N failed tasks |
| `stats` | Hash | All five dashboard metrics in one call |

`stats` has a **default implementation** in `Base` that delegates to the five individual methods — suitable for SQL-backed adapters (five cheap queries). Redis overrides it with a single `LRANGE` pass.

### `filters` hash keys

All values are pre-validated non-blank strings; absent keys mean "no filter".

| Key | Type | Meaning |
|---|---|---|
| `:task_name` | String | Exact match |
| `:status` | String | `"success"` or `"failure"` |
| `:hostname` | String | Exact match |
| `:rails_env` | String | Exact match |
| `:from` | String (date) | `started_at >=` |
| `:to` | String (date) | `started_at <=` |

### `ExecutionRecord` (non-AR adapters)

`RakeAudit::Adapters::ExecutionRecord` is a Struct with all 12 execution fields plus `id` and `to_param`, so Rails route helpers work without ActiveRecord:

```ruby
ExecutionRecord = Struct.new(
  :id, :task_name, :arguments, :started_at, :finished_at,
  :duration_ms, :status, :error_class, :error_message,
  :hostname, :pid, :ruby_version, :rails_env,
  keyword_init: true
) do
  def to_param = id.to_s
end
```

### Record IDs by adapter

| Adapter | ID type | Notes |
|---|---|---|
| `ActiveRecordAdapter` | Integer (auto-increment) | AR model `id` |
| `RedisAdapter` | UUID string | Generated by `SecureRandom.uuid` at save time and embedded in the JSON |
| `MongoAdapter` | ObjectId string | Mongo's native `_id`, converted via `.to_s` |

## ApplicationController

```ruby
module RakeAudit
  class ApplicationController < ActionController::Base
    before_action :authenticate!
    rescue_from RakeAudit::RecordNotFound, with: :record_not_found

    private

    def authenticate!
      return unless RakeAudit.config.authenticate_with
      instance_exec(self, &RakeAudit.config.authenticate_with)
    end

    # Returns the configured adapter. Falls back to ActiveRecordAdapter when
    # config.adapter is nil (logs a warning so operators know to configure it).
    def web_adapter
      RakeAudit.config.adapter || default_web_adapter
    end

    def default_web_adapter
      RakeAudit.config.logger.warn(
        '[RakeAudit] config.adapter is nil — falling back to ActiveRecordAdapter. ' \
        'Set RakeAudit.configure { |c| c.adapter = ... } in your initializer.'
      )
      RakeAudit::Adapters::ActiveRecordAdapter.new
    end

    def record_not_found
      head :not_found
    end
  end
end
```

## ExecutionsController

```ruby
module RakeAudit
  class ExecutionsController < ApplicationController
    def index
      @executions = web_adapter.query(filters: filter_params, page: params[:page])
    end

    def show
      @execution = web_adapter.find(params[:id])
    end

    private

    def filter_params
      {
        task_name: params[:task_name],
        status:    params[:status],
        hostname:  params[:hostname],
        rails_env: params[:rails_env],
        from:      params[:from],
        to:        params[:to]
      }.reject { |_, v| v.blank? }
    end
  end
end
```

## DashboardController

```ruby
module RakeAudit
  class DashboardController < ApplicationController
    def index
      s = web_adapter.stats
      @total               = s[:total]
      @success_count       = s[:success_count]
      @failure_count       = s[:failure_count]
      @failure_rate        = failure_rate(@failure_count, @total)
      @average_duration_ms = s[:average_duration_ms]
      @top_failed_tasks    = s[:top_failed_tasks]
    end
  end
end
```

`stats` is a single adapter call so Redis only reads the full list **once** per dashboard request (vs. five separate reads if calling individual methods).

## Execution List Page

Filter form fields: `task_name` (text), `status` (select: all/success/failure), `hostname` (text), `rails_env` (text), `from` date, `to` date.

Table columns: Task Name | Status | Duration (ms) | Started At | Hostname | Rails Env | (link to detail)

Pagination via kaminari (AR adapter returns a kaminari AR relation; Redis/Mongo adapters return `Kaminari.paginate_array(...)`).

## Adapter Configuration Examples

### ActiveRecord (default)

```ruby
RakeAudit.configure do |config|
  config.adapter = RakeAudit::Adapters::ActiveRecordAdapter.new
end
```

Requires the migration to be run (`rake rake_audit:install:migrations && rake db:migrate`).

### Redis

```ruby
RakeAudit.configure do |config|
  config.adapter = RakeAudit::Adapters::RedisAdapter.new(client: Redis.new)
end
```

Each saved record is prepended to the `rake_audit:executions` list key with a UUID `id` field embedded in the JSON. The Web UI reads the full list for each query; suitable for low-to-moderate record volumes.

### MongoDB

```ruby
RakeAudit.configure do |config|
  config.adapter = RakeAudit::Adapters::MongoAdapter.new(
    client: Mongo::Client.new(['localhost:27017'], database: 'myapp')
  )
end
```

Requires the `bson` gem. Uses Mongo's native `_id` (ObjectId) as the record identifier. All queries are pushed to the server (filter, sort, pagination, aggregation).
